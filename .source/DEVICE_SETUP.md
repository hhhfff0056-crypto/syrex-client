# Syrex: сайт ↔ Minecraft-клиент, вход и HWID

## Внутриигровая авторизация (готовые Java-классы)

Добавлены следующие исходники (имена классов Minecraft в Mojang mappings, 1.21.11):

- `client-integration/java/com/syrex/auth/SyrexAccountClient.java` — вход через Supabase.
- `client-integration/java/com/syrex/auth/SyrexLoginScreen.java` — **настоящий Minecraft Screen**: поля email/пароль, скрытое отображение пароля, постоянное предупреждение об обязательной привязке устройства (без отдельной галочки), асинхронный вход, состояние ошибки, переход в клиент после входа.
- `client-integration/java/com/syrex/auth/SyrexAuthGate.java` — открытие экрана и in-memory текущая сессия.

В исходниках **реального** клиента (после получения их отдельной доступной копии) добавьте эти классы и вызовите экран, когда Minecraft готов показывать GUI:

```java
SyrexAuthGate.showLogin(
    "<Supabase publishable key, НЕ service_role>",
    () -> existingClientHwidProvider.getStableHwid()
);
```

`existingClientHwidProvider` — пример: нужно подставить реальную функцию
чтения HWID из **исходников** Syrex; она должна работать локально.
Нельзя подключить этот вызов без знания конкретного класса и места инициализации
мода. Для клиентов с Yarn mappings потребуются соответствующие имена Minecraft
классов или remapping.

**Внимание:** экран и API созданы в репозитории сайта как исходники для интеграции,
а не встроены в JAR на Google Drive. В существующем архиве не внесены изменения.
Пока не интегрирован startup hook и защита функций, режим Premium нельзя считать
полностью защищённым: статус от UI не заменяет серверную проверку.
Также для долгой сессии следует реализовать безопасное обновление Supabase JWT
и повторную проверку лицензии: экран сейчас выполняет ручной вход на каждый запуск.

## Как подключить Java-клиент

1. Добавьте `SyrexAccountClient.java` в Java-проект Minecraft. Используйте
   уже имеющийся Gson; не помещайте `service_role` или секретные ключи в JAR.
2. При входе пользователя с уведомлением об обязательной привязке получите стабильный HWID
   через уже имеющийся **локальный** HWID-провайдер вашего клиента.
   Передайте в `loginAndBind(email, password, localHwid)` **локальный** HWID.
   Адаптер сам отправляет только `SHA-256("syrex-hwid-v1:" + localHwid)`.
   Не записывайте сырой HWID в логи, чат, telemetry или файлы.
3. В конструктор передайте URL `https://schhzjmsgdjicoiadoqx.supabase.co`
   и **публичный** `VITE_SUPABASE_PUBLISHABLE_KEY` из конфигурации сайта.
   Его можно использовать в публичном клиенте. Секретные ключи туда не копируйте.
4. Успешный вход возвращает `LoginResult`: токены сеанса, числовой UID, редакцию
   FREE/PREMIUM и срок лицензии. Не сохраняйте пароль. При старте игры проверяйте
   уже активный сеанс через `verify(accessToken, localHwid)`. Обновление
   `accessToken` через Supabase refresh-token endpoint при истечении токена
   необходимо добавить в существующий менеджер сессий; адаптер пока этого
   автоматически не делает.
5. Если сервер ответил `409 DEVICE_MISMATCH`, показывайте сообщение о другой
   привязке и не открывайте защищённые Premium-функции. Проверка только в
   интерфейсе клиента не является криптографической защитой от модификации JAR.

## Протокол API

Все запросы: HTTPS POST `/functions/v1/syrex-device`, заголовки
`apikey: <publishable_key>`, `Authorization: Bearer <Supabase_access_token>`,
`Content-Type: application/json`.

- `{"action":"status"}` — для сайта: `bound`, `boundAt`, `lastSeenAt`.
- `{"action":"bind","hwidHash":"<64 hex characters>"}` — привязывает при первом
  входе или проверяет при последующих. Ответ: `success`, `bound`, `uid`,
  `edition`, `premium`, `expiresAt`.
- `{"action":"verify","hwidHash":"<64 hex characters>"}` — только проверка,
  не привязывает новый ПК.
- При конфликте: HTTP 409 и `code: "DEVICE_MISMATCH"`. При отсутствии первичной
  привязки на verify: `code: "DEVICE_NOT_BOUND"`.

HWID не хранится в базе в исходном виде: клиент передаёт хеш, а сервер
хранит дополнительный SHA-256 с случайной солью для каждого аккаунта.

## Сброс HWID

Автоматического общедоступного сброса нет: это позволило бы обходить привязку.
Подтверждённый администратор после проверки обращения может удалить строку
`syrex_device_bindings` нужного `user_id` через защищённый серверный инструмент.
При следующем входе пользователь привяжет новое устройство.
Тариф HWID Reset на сайте не является автоматическим платёжным обработчиком.

## Проверка перед релизом

- Регистрация на сайте → вход в клиент теми же email/паролем → привязка.
- В профиле отображается «Привязан».
- Повторный вход с тем же HWID проходит, с другим — `DEVICE_MISMATCH`.
- Free показывает FREE, Premium показывает PREMIUM только при действительной лицензии.
- Срок лицензии истекает и сервер возвращает FREE.
- JWT отсутствует/неверный → HTTP 401. Другой пользователь не может узнать
  чужой HWID или изменить чужую привязку.
