# Syrex Client — система ключей

Аккаунты: Supabase Auth. Одноразовые ключи: syrex_activation_keys. Лицензии: syrex_licenses. Попытки: syrex_activation_attempts.
Три таблицы используют RLS без политик публичного доступа. Активация идёт через серверную функцию syrex-keys.

## Для пользователей
1. Войти в аккаунт Syrex и открыть /keys из Личного кабинета.
2. Вставить одноразовый ключ формата SYREX-XXXXX-XXXXX-XXXXX-XXXXX.
3. Лицензия привязывается к аккаунту, а не браузеру. После истечения срока можно активировать новый.
4. Активный пользователь скачивает файл по подписанной ссылке на 60 секунд.

## Для разработчика DEV
Роль проверяется по Supabase Auth app_metadata.role на сервере. Только DEV может выпустить 1–10 кодов за раз на 7/30/90/365 дней или навсегда.
Полные значения отображаются однократно и не сохраняются в базе. Хранится SHA-256 каждого случайного 100-битного ключа.
Роль DEV может скачивать файл без ключа. Число неудачных попыток активации ограничено 8 за 10 минут для каждого аккаунта.

## Загрузка клиента
В репозитории файла .jar нет. Откройте https://supabase.com/dashboard/project/schhzjmsgdjicoiadoqx/storage/buckets
В закрытый бакет syrex-client (Public OFF) загрузите собственный файл ровно с именем SyrexClient.jar в корень бакета.
Никогда не делайте бакет публичным: это снимет серверную проверку ключей.
До загрузки файла кнопка скачивания остаётся недоступной и показывает честный статус.

## Ограничения
Скачанный пользователем файл может быть скопирован за пределы сайта: контроль выдачи не является DRM в Minecraft.
Старая /admin использует прежний локальный API и не связана с работающими ключами. Рабочая генерация на /keys.
